# 引言（中文对照稿）

对应 `paper.tex` 的 Introduction，英文正文为论文目标稿。

功能性全系统仿真支持未经修改的系统软件跨宿主架构运行，通常优先保证执行速度，并允许有界的时间偏差。QEMU 的 MTTCG 支持多个虚拟 CPU 并行执行；其指令计数模式能够根据 Guest 指令推进虚拟时间，但多个虚拟 CPU 由单个线程执行。时钟周期精确模拟器可提供更高的时序精度，同时需要显著更多的计算资源。许多系统软件依赖定时器判断处理是否超时；通信芯片的功能仿真是这类问题的一个典型场景。在这一场景下，Guest 时间应依据目标硬件标定结果，随指令执行进度推进。若时钟直接随宿主时间推进，就可能超前于仿真软件的处理进度，产生目标硬件上不会出现的超时。

SkewKeeper 为并行虚拟 CPU 建立逻辑指令时间线，以活动核的最小进度为基准，通过有界偏斜窗口约束各核的执行超前量。协调器周期性发布指令驱动的模型时间；在发布间隔内，共享可见时钟依据历史进度进行动量加权插值。读时限幅将可见时间约束在模型时间附近，缓解计数器平台期，并维持跨核单调的统一时间基准。

SkewKeeper 结合有界执行滑窗与动量插值，为并行虚拟 CPU 建立共享的指令驱动时间基准。Linux 启动与 jitterentropy 持续运行覆盖了依赖定时器的软件路径，多核测量则将其执行开销置于 icount 和 MTTCG 的对照下。面对宿主执行能力的变化，具有截止时间约束的通信负载仍保持预期的 Guest 时间行为。通过协调可见时间状态与插值动量，同一时间基准也延续至 skew 和 MTTCG 的运行时切换过程。
