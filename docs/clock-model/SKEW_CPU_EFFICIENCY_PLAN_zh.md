# Skew CPU 执行效率优化计划

日期：2026-10-18  
基线：`skew-v10.2.0` / `16ec93bd1cbcb651ba9e3b616bdc1b26ddcc54b1`  
工作分支：`codex/skew-cpu-efficiency`

## 目标与约束

提高真实 QEMU / Guest 工作中的有效执行效率，减少 16 位预算分段、BQL 往返、
窗口等待及全局进度发布引入的停顿。保留 MTTCG 并行、滑窗、精确完成计数、
真实 idle 成员管理、可见时间插值和动态模式切换。

必须保持：

- 活跃 CPU 的逻辑进度由已完成指令形成；不预记下一段指令。
- `global_icount` 单调前进，正常运行受活跃成员最小进度约束。
- 发放预算满足 `local + budget <= grant_global + window`。
- 窗口等待者继续属于 active；WFI、停机等真实 idle 按原有规则退出集合。
- 重新加入在同一同步区间取得 global 并建立 raw/logical 基准。
- 预算操作保留递减器高位的异步退出通知，精确处理异常回退和原子重试。
- 暂停和双向模式切换先停稳 vCPU，完成旧预算结算，再重锚时间。
- 设备、MMIO、中断等原有 QEMU 同步要求继续成立。

历史对话中的 65.3% 窗口调用/等待和 22.7% 显式 BQL 获取使用累计线程墙钟；
该口径包含睡眠、取锁与宿主调度延迟，不能解释成等量宿主 CPU 算力消耗。
宿主配额、Guest 核数、二进制和工作量必须随结果记录。

## P0：建立可复现入口

状态：已完成构建及可用功能基线。宿主线程 schedstat 不可见，相关测量明确省略。

1. 构建本分支的 aarch64-softmmu，保留日志、版本、编译配置及宿主资源信息。
2. 运行公共预算单测及现有快速真实 Guest 验收，确认当前环境可运行。
3. 保存基线二进制及明确的同工作量命令，后续与优化二进制分别运行。
4. 每个子进程、单项测试和整组任务均设置宿主超时；失败保留日志，回收子进程。
5. 性能采样与带 trace 的正确性验收分开，不使用高频 QMP 轮询扰动性能结果。

验收：构建和基线结果可追溯；超时能结束测试并留下失败证据。

## P1：窗口内续配预算

状态：已实现并通过定向回归、15 项真实 Guest 检查及 32 vCPU Linux 检查。
命令、覆盖范围及测量限制见 [验证记录](SKEW_CPU_EFFICIENCY_VALIDATION_zh.md)。

- 分离窗口额度与 TCG 的 16 位计数槽。
- 计数槽耗尽后在 CPU 执行循环内结算并原子发布完成量；窗口仍有额度时续配。
- 同时检查 exhausted / expired 两处调用，防止公共循环在续配前提前退出。
- 保留短 TB、异常回退、复位前结算、异步退出及原子重试语义。
- 窗口边界仍按安全条件退出；不靠扩大窗口取得收益。

验收：精确计数、1 条指令窗口、65535 边界及多段窗口通过；
窗口内续配减少外层退出；暂停、复位及计数高位保持通过。

## P2：窗口等待脱离 BQL

状态：待执行。

- 预算边界从 cpu_exec 返回并结束执行临界区，再进行窗口等待。
- 每个已配置 vCPU 使用独立事件；纯窗口恢复可直接续配并再次执行。
- QEMU 的 kick、暂停、异步工作、中断及退出请求能够打断等待并回到原生事件处理。
- 检查、事件复位、等待者登记和通知采用一致协议，覆盖通知先于睡眠的交错。
- 不在 RCU 读侧执行区或持有 BQL / 进度锁时阻塞。

验收：真实 Guest 的窗口睡眠/恢复、WFI、中断、异步控制、暂停/恢复和退出通过；
32 vCPU 条件下没有漏唤醒或僵死。

## P3：全局进度协调脱离 BQL

状态：待执行。

- 原子发布 global，由短时持有的 skew 专用锁串行化成员变更与最小进度扫描。
- 由 vCPU 完成量提交和边界请求触发协调；采用协作推进，避免增加常驻协调线程。
- CPU 列表扫描使用 QEMU 的 RCU 生命周期规则。
- 锁顺序统一为 BQL → skew 进度锁；进度锁内禁止获取 BQL或阻塞等待。
- 进度发布与窗口通知独立于主线程；主线程仍按协调周期更新插值和设备时钟。
- 同步检查 QMP 快照、全 idle 尾部提交、idle warp 及模式重置路径。
- 调整 trace 验收，使其验证发放时的窗口约束与已完成进度，支持周期之间的推进。

验收：慢核约束、成员加入/退出、全 idle warp、时间单调性、插值边界和动态切换通过；
窗口释放不再依赖主线程取得 BQL。
